# マッパ（MAPPA）— 動くプロトタイプ

温浴施設（サウナ・スーパー銭湯）のプロモーション枠を、広告主・提携施設・運営会社の3者で
やりとりするための **社内向け業務システム** の動作するプロトタイプです。

左サイドメニュー・ツールバー・罫線グリッド・ステータスバーという、
一般的な業務システムの構成にしています。装飾より情報密度と一覧性を優先。

**全国80施設・252枠**（47都道府県すべて）のプレビューデータが入っています。

**プレビュー → https://playmark0227-svg.github.io/mappa-preview/**

---

## これは何ができるのか

画面のモックではなく、**在庫エンジンが実際に動いています**。

| できること | 中身 |
|---|---|
| 空き枠の検索 | エリア・期間・枠タイプ・商材カテゴリ・予算・客層で絞り込み。**指定期間に実際に空きがある枠だけ**が「空きあり」になります |
| 空き状況カレンダー | 枠商品ごとの日次在庫。空きあり／残りわずか／満枠／受入不可／選べません の5状態 |
| 設置マップ | **実際のタイル地図**（既定は国土地理院タイル）に提携施設80件をプロットし、**基準日時点でどこに何が設置されているか**を表示。街区レベルまでズームできる。施設を選ぶと館内のゾーン別（男性脱衣所／女性脱衣所／エントランス等）に何が置かれているかまで降りられる。施設×カテゴリのマトリクスで俯瞰も可能 |
| 制約の検証 | 最短リードタイム・最小最大日数・予約可能地平・最低出稿金額・**競合カテゴリ排他**をすべてチェック |
| 仮押さえと決済 | 申込で30分の仮押さえ（カウントダウン付き）。決済でその枠が確定し、在庫から引かれます |
| キャンセルと返金 | 実施日までの日数から返金率（100/70/50/30/0%）を自動計算 |
| 施設側の在庫入力 | スマホ想定のカレンダーから、日をタップして受入不可を登録。予約が入っている日はブロックできません |
| 3者の連動 | 施設が受入不可にした日は、**広告主の検索結果とカレンダーに即座に反映**されます |

### 試してみる順番

1. トップの「空き枠をさがす」→ 気になる施設の「詳しく見る」
2. 右のウィジェットで期間を選び「この枠を予約する」
   （満枠なら「空いている最短日程を提案」が使えます）
3. 3ステップを進めて決済（テスト用のダミーカードが入力済みです）
4. 右上の役割スイッチで **施設** に切り替え → 今日のタスクに受注が出ています
5. 「スケジュール」で適当な日をタップして受入不可に
6. **広告主** に戻ると、その日がカレンダーで「受入不可」になっています
7. **運営** に切り替えると、GMV と予約横断一覧に反映されています
8. 「設置マップ」で基準日を動かすと、その日に全国のどこへ何が置かれているかが変わります

## 技術メモ

- 依存パッケージ・ビルド不要の静的サイト（HTML + CSS + ES Modules）。GitHub Pages にそのまま載ります。
- Webフォントは使わず OS 標準フォント。数値・日付・ID は等幅で桁を揃えています。
- 地図は Leaflet 1.9.4（**リポジトリに同梱**。CDNに依存しないので社内プロキシ環境でも動きます）。
  地図の DOM は画面再描画の対象外に置き、インスタンスを作り直しません
  （Leaflet は `map.remove()` を呼ばないと window の resize リスナが残るため）。
  切り替えられるベースマップ:
  **国土地理院タイル（淡色 / 標準 / 航空写真）** … APIキー不要、既定
  **OpenStreetMap** … APIキー不要
  **Google Maps** … 利用者が自分の Maps JavaScript API キーを入力したときのみ有効。
  キーはそのブラウザの localStorage にのみ保存し、こちらのサーバーには送りません。
  未入力の間は地理院タイルを表示します。
- 在庫の埋まり具合と「何が設置されているか」は同じ生成元から導いているため、
  満枠なのに設置内容が空、といった食い違いが起きません。同一カテゴリの同時設置も起こしません。
- 施設データは実在の街・駅を素データにし、客層・枠・料金・実績は決定的な擬似乱数で導出。
  誰が開いても同じ内容になります（実在の施設・実在の数値ではありません）。
- 予約・受入不可の設定は **閲覧しているブラウザの localStorage にのみ** 保存されます。
  他の人には見えません。フッターの「デモデータを初期化」でいつでも元に戻せます。
- 決済は発生しません。Stripe との通信は一切していません。

```
index.html
assets/
  data.js     … 施設マスタ・在庫エンジン・設置状況・料金/返金の計算
  japan.js    … 都道府県ポリゴン（簡略化・埋め込み）
  styles.css  … デザインシステム
  app.js      … ルーターと全画面
```

## 本番実装との差分

このプロトタイプは体験の検証用です。本番では次が必要になります。

- 在庫の排他制御をサーバー側（PostgreSQL の行ロックと `CHECK` 制約）で行う
- Stripe Checkout と webhook による確定処理
- 施設・広告主・運営の認証と行レベルのアクセス制御
- 適格請求書の発行と施設への月次支払

設計の詳細は別途の MVP 設計書にまとめています。

## 運用上の注意

- **Google Maps を使う場合は、APIキーに必ず制限をかけてください。**
  Cloud Console で ①アプリケーションの制限＝HTTPリファラー（`https://<組織>.github.io/mappa-preview/*` のように
  パスまで限定。`*.github.io/*` は他組織からも通るので不可）②APIの制限＝Maps JavaScript API のみ
  ③マップロードの1日上限と予算アラート、の3点を設定してください。
  キーはブラウザから読める前提の作りです（Maps JavaScript API の仕様上、隠せません）。
- **OpenStreetMap のタイルは社外公開には向きません。** OSM の Tile Usage Policy は
  タイル配信をコミュニティ向けと位置づけており、第三者向けプロダクトの常設ベースマップは想定外です。
  社外に開放する段階では地理院タイル単独にするか、商用タイル（MapTiler / Stadia / Carto 等）へ移行してください。
- **地理院タイル**は出典表示（「地理院タイル」＋地理院タイル一覧ページへのリンク）が要件で、
  地図左下の attribution がそれにあたります。**この表示を消さないでください。**
